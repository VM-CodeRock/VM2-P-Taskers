Restoration Procedure for Paused Crons

How to Restore a Paused Cron

Paused crons are NOT deleted — their full task bodies are preserved in cron_tracking/cron_backup_2026-06-03.json. Restoration creates a new cron with a new ID; the old ID is retired.

  1. Obtain user authorization to restore the specific cron(s).
  2. Open /home/user/workspace/cron_tracking/cron_backup_2026-06-03.json.
  3. Locate the entry by cron ID (e.g., 27d43c4a).
  4. Copy the task field content verbatim — this is the complete instruction set.
  5. Copy the cron field for the original schedule string.
  6. Run: pplx-tool schedule_cron action=create cron="<original_schedule>" task="<copied_task_body>" using api_credentials=["pplx-tool:schedule_cron"].
  7. The restored cron will receive a new ID. Update cron_tracking/cron_backup_2026-06-03.json with the new ID for future reference.
  8. Update the next System Docs Auto-Update run to reflect the restored cron.

08k Gmail Intake Race Condition with Audit Cron (v3.3)

Audit Race Condition — Issue #5 (CONFIRMED 5/27)

If cron 5cfbd2ec (Deliverable Integrity Audit) flags an email as “missed intake CRITICAL” but a subagent is concurrently processing that email, it is a race condition false positive — NOT a real compliance failure. Do NOT escalate.

Detection: Check for any in-flight subagent work on the same email_id before treating as a real miss.

Remediation (if applicable): Verify the deliverable was produced. If yes, add the email_id to processed_email_ids in state.json and verify portal.html entry exists.

08n Recurring Todoist Deferred-State Workaround (v3.6)

Deferred-State Workaround — Validated 2026-06-04 to 06-05 v3.6 New

When a recurring Todoist task must be suppressed without destructive label changes (e.g., during a cost-optimization pause), marking the task state as deferred_cost_optimization in recurring_state.json successfully prevents the cron escalation loop.

Use case: Paused crons with recurring Todoist tasks (e.g., Daily Executive Agenda c40cee7b) would otherwise trigger escalation when the Todoist Execution cron 64b6a5cc sees an overdue task.

Procedure:

  1. Locate the recurring task entry in cron_tracking/todoist_vm2/recurring_state.json.
  2. Set the status field to "deferred_cost_optimization".
  3. Set resume_date to the expected restore date or null if open-ended.
  4. The Todoist Execution cron will read this state and skip escalation for deferred tasks.

08o Compliance Auto-Remediation Pattern — Issue #18 (NEW v3.7)

Auto-Remediation Established — 2026-06-13 v3.7 New

Compliance Audit cron 6494d39d ran on 6/13/2026 and auto-remediated two deliverables (ai-daily-2026-06-12.html and ateps-ii-sam-check-2026-06-12.html) that were missing literal JSON context slug markers. Commit cd13b0e. This pattern is now the approved auto-fix workflow for Rule 6 violations.

Trigger conditions: Deliverable missing one or more of: literal "context_slug" key, literal "deliverable" key, or literal "cost_estimate" key in the JSON script block. HTML-escaped variants (&quot;, &lt;, etc.) are also treated as non-compliant starting v3.7.

Auto-fix procedure (performed by Compliance Audit 6494d39d):

  1. Read the non-compliant HTML file from /home/user/workspace/VM2-P-Taskers/.
  2. Locate the <script type="application/json" id="vm2-context-data"> block.
  3. If block exists: inject missing literal JSON fields (context_slug, deliverable, cost_estimate) into the existing JSON.
