APFS RAG Schema Drift — Normalizer Patch (v2.9) + APFS Query Builder (Issue #10, v3.3)

The RAG endpoint schema changed on 5/18. The APFS cron 8734a0c6 normalizer expected the old schema and needed an inline patch. v3.3 update (5/27): Issue #10 confirmed — the parser was also using record.get('title') which is null for APFS records.

⚠ Issue #10 — APFS RAG Parser Field Mismatch (INLINE PATCHED 5/27, permanent fix pending)

Cron 8734a0c6 was building the RAG query using record.get('title'), which is null for APFS records. The correct composite query uses two real APFS fields:

Agency: {org}
Title: {requirements_title}
NAICS: {naics}
Vehicle: {contract_vehicle}
Description: {requirement}

Asterisk-prefix rule: APFS numbers like *F2025071074 must be preserved verbatim (the asterisk is a unique key prefix — do NOT strip it). 4 records inline-patched 5/27: F2026073183, F2026073425, F2026073890, *F2025071074 (all returned LOW 0.30–0.32 with correct query).

load_skill Failure in Cron Subagents — Workaround (Issue #7)

Background crons CANNOT load user skills via load_skill(). This is a known platform behavior, not a bug. The workaround is to read skill files directly from disk:

1
Instead of load_skill(name="changeis-style"), use the read tool on the file path: /home/user/workspace/skills/user/changeis-style/Changeis_Refined_Document_Style.md
2
Apply the same pattern for any user skill. The SKILL.md or primary markdown file contains all needed instructions.
3
Cron instructions should explicitly reference the read-from-file workaround in their preamble going forward.
