Task Close-Out Procedures (v3.9 — Formalized)

One-shot and recurring tasks use distinct close-out flows. Do not mix them.

A
One-Shot Tasks (VM2 label only, no vm2-recurring): (1) GET task from Todoist REST API. (2) Add vm2-done label. (3) POST /api/v1/tasks/{id}/close with X-Request-Id (UUID4). (4) Update cron_tracking/todoist_vm2/state.json — NOT recurring_state.json.
B
Recurring Tasks (VM2 + vm2-recurring): (1) GET task from Todoist REST API. (2) Append delivery log line to description: YYYY-MM-DD Delivered: {URL}. (3) POST /api/v1/tasks/{id} with updated description + X-Request-Id (UUID4). (4) POST /api/v1/tasks/{id}/close with X-Request-Id (UUID4). (5) Append entry to cron_tracking/todoist_vm2/recurring_state.json.

Context Slug Compliance — Literal JSON Required (Issue #16/#18)

All deliverables must include a <script type="application/json" id="vm2-context-data"> block with literal (not HTML-escaped) JSON markers. The Compliance Audit enforces this weekly.

LITERAL JSON REQUIRED — HTML-Escaped Markers Rejected (v3.7+)
Deliverables must contain literal "context_slug", "deliverable", and "cost_estimate" fields inside the JSON script block. HTML-escaped variants are not accepted. The auto-remediation pattern (Issue #18) injects these on detection.
load_skill Failure in Cron Subagents — Workaround (Issue #7)

Background crons CANNOT load user skills via load_skill(). This is a known platform behavior, not a bug. The workaround is to read skill files directly from disk:

1
Instead of load_skill(name="changeis-style"), use the read tool on the file path: /home/user/workspace/skills/user/changeis-style/Changeis_Refined_Document_Style.md
2
Apply the same pattern for any user skill. The SKILL.md or primary markdown file contains all needed instructions.
