It runs 14 scheduled tasks that automate daily executive briefings, federal opportunity intelligence, task automation, compliance and governance, and business development. As of May 30, 2026: ~972 deliverables, 14 active crons, 5 user skills.

08g SAM Stuck-Run Cleanup Procedure (Issue #13)

# 1. Remove stale lockfile
rm -f /home/user/workspace/data/sam/.daily_monitor.lock

# 2. Clear orphaned in_progress run
sqlite3 /home/user/workspace/data/sam/sam.sqlite \
  "UPDATE runs SET status='failed', end_time=datetime('now') \
   WHERE status='in_progress' AND start_time < datetime('now','-2 hours');"

# 3. Re-run the monitor
python3 /home/user/workspace/data/sam/daily_monitor.py

08h APFS RAG Schema Drift Detection (v2.9)

New response schema: {query, matches[], best_match, best_score, tier}. Each match has composite_score. Use tier for classification. Use max(matches[].composite_score) for APFS scoring. Tiers: STRONG ≥0.65, MODERATE 0.50–0.64, RELEVANT 0.45–0.49, LOW <0.45.

08j APFS RAG Recovery — Issue #10 (v3.3)

⚠ Issue #10 — APFS RAG Parser Field Mismatch (INLINE PATCHED 5/27, permanent fix pending)

Cron 8734a0c6 was building the RAG query using record.get('title'), which is null for APFS records. The correct composite query:

Agency: {org}
Title: {requirements_title}
NAICS: {naics}
Vehicle: {contract_vehicle}
Description: {requirement}

Asterisk-prefix rule: APFS numbers like *F2025071074 must be preserved verbatim (the asterisk is a unique key prefix — do NOT strip it).

4 records inline-patched 5/27: F2026073183, F2026073425, F2026073890, *F2025071074 (all returned LOW 0.30–0.32 with correct query). Permanent script fix still pending authorization.

08k Gmail Intake Race Condition with Audit Cron (v3.3)

Audit Race Condition — Issue #5 (CONFIRMED 5/27)

If cron 5cfbd2ec (Deliverable Integrity Audit) flags an email as “missed intake CRITICAL” but a subagent is concurrently processing that email, it is a race condition false positive — NOT a real compliance failure. Do NOT escalate.

Detection: Check for any in-flight subagent work on the same email_id before treating as a real miss. The 5/27 1 PM run flagged ASSC FAA (email_id 19e6a58528edf9c1) as missed while a subagent was processing it.

Remediation (if applicable): Verify the deliverable was produced. If yes, add the email_id to processed_email_ids in state.json and verify portal.html entry exists.
