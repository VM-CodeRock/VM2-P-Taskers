01 System Overview & Architecture

What is VM2?

VM2 ("Varun Malhotra 2") is an automated Chief-of-Staff AI system built on Perplexity Computer for Varun Malhotra, President of Changeis Inc. It runs 14 scheduled tasks that automate:

  • Daily Executive Agenda — Morning briefing with calendar, email triage, and task priorities
  • Federal Opportunity Intelligence — Monitoring DHS APFS and SAM.gov for contract opportunities, RAG-scoring them against Changeis past performance, and generating deep-dive analyses
  • Task Automation — Executing tasks from Todoist (VM2 label) and Gmail (vm2.viru@gmail.com)
  • Compliance & Governance — Nightly audits, weekly digests, monthly integrity checks, deliverable integrity audits
  • Business Development — YPO introduction tracking, Todoist auto-helper suggestions, MAPS amendment monitoring

08g SAM Stuck-Run Cleanup Procedure (v2.6) NEW v2.6

When daily_monitor.py is killed mid-run, it may leave a row in the runs table with status='in_progress'.

Cleanup Procedure

  1. Verify lockfile is absent: ls -la /home/user/workspace/data/sam/.daily_monitor.lock 2>/dev/null || echo "No lockfile"
  2. Check for orphaned in-progress run: sqlite3 /home/user/workspace/data/sam/sam.sqlite "SELECT id, start_time, status FROM runs WHERE status='in_progress';"
  3. If orphaned row found: sqlite3 /home/user/workspace/data/sam/sam.sqlite "UPDATE runs SET status='failed', end_time=datetime('now') WHERE status='in_progress' AND start_time < datetime('now','-2 hours');"
  4. Remove stale lockfile: rm -f /home/user/workspace/data/sam/.daily_monitor.lock
  5. Re-run the monitor: python3 /home/user/workspace/data/sam/daily_monitor.py

08h APFS RAG Schema Drift Detection (v2.9) NEW v2.9

The RAG engine endpoint schema changed on 2026-05-20. Cron 8734a0c6 normalizer expected the old schema and produced incorrect scoring until an inline patch was applied.

Schema Change Detected 5/18/2026

The RAG endpoint POST /match now returns a different JSON structure. Old normalizer (pre-v2.9) used classification, top_score, and top_matches[]. These keys no longer exist in the response.

Old vs. New Schema

def parse_rag_response(response_json):
    """Parse v2.9 RAG engine response. Use composite_score for per-match scoring."""
    tier = response_json.get("tier", "LOW")           # was: classification
    best_score = response_json.get("best_score", 0.0)  # was: top_score

            "score": score,
            "tier": "STRONG" if score >= 0.65 else
                    "MODERATE" if score >= 0.50 else
                    "RELEVANT" if score >= 0.45 else "LOW"
        })

        "best_match": response_json.get("best_match"),  # NEW: explicit best match
        "scored_matches": scored
    }

Key Lessons Learned

  • Auto-dive was removed (v2.2) because it created tasks Varun didn't request. Daily brief is INFORMATIONAL ONLY.
  • portal.html must insert rows after <tbody id="tableBody"> with proper data attributes for filtering to work.
  • (v2.6) SAM hardening: SQLite WAL mode + busy_timeout + lockfile prevents the concurrent-run lock error.
  • (v2.6) REST-first rule: audit and task-execution crons must use REST API as primary. NEVER escalate on connector status alone.
  • (v2.6) Subagent ID verification: always verify IDs against a fresh REST fetch before acting.
  • (v2.9) RAG schema drift: the endpoint schema is not guaranteed stable. When all opportunities score 0.00/LOW, suspect a schema change. Re-fetch one record and compare against known schema to diagnose.
  • (v2.9) Builder date-pin: any builder script that uses a hardcoded date in its filename or variable will break as soon as the date changes. All builders must use datetime.utcnow().date() at write-time.
  • (v2.9) MAPS monitor: do not deactivate on response deadline alone. Government protest landscape can extend obligation well beyond the initial deadline.
  • (v2.9) Audit false-positives: non-task emails (folder invites, OOO replies) that arrive in the VM2 inbox must be immediately tagged in processed_email_ids state to prevent repeat false-positive flagging.
